# Block Build

Спокойная браузерная головоломка. TypeScript + Vite, Canvas 2D для поля и фигур, HTML/CSS для интерфейса. Игровые ресурсы локальные; внешних шрифтов, CDN и runtime-запросов к сервисам нет.

## Запуск и сборка

Требуется Node.js ≥ 22.12 и pnpm 11.19 (или npm).

```sh
pnpm install --frozen-lockfile
pnpm dev --port 4173
```

Открыть http://localhost:4173. Альтернатива: `npm install`, `npm run dev -- --port 4173`.

```sh
pnpm check         # TypeScript и правила поля
pnpm build         # готовый статический сайт в dist/
pnpm preview --port 4174
pnpm test:e2e      # при запущенном dev-сервере :4173; нужен Google Chrome
```

Содержимое `dist/` публикуется на статическом HTTP-хостинге. `file://` для ES-модулей не подходит. Установка зависимостей требует сеть, сама игра — нет.

### Публикация на GitHub Pages

1. В репозитории открыть **Settings → Pages → Build and deployment → Source** и выбрать **GitHub Actions**.
2. Закоммитить и отправить изменения в `main`. Workflow `.github/workflows/deploy.yml` установит зависимости, выполнит `pnpm check` и `pnpm build`, затем опубликует `dist/`.
3. Дождаться успешного **Actions → Deploy to GitHub Pages**. Страница будет доступна по адресу https://zluza.github.io/HVTestTask/; точная ссылка также появится в результате deployment.

Повторная публикация запускается при каждом push в `main`. Её можно запустить вручную через **Actions → Deploy to GitHub Pages → Run workflow**.

Папку `dist/` коммитить не нужно: GitHub Actions создаёт её при сборке. Относительная база `./` в `vite.config.ts` и пути картинок через `import.meta.env.BASE_URL` позволяют размещать игру в подпапке репозитория. Основа настройки — [официальная инструкция Vite для GitHub Pages](https://vite.dev/guide/static-deploy.html#github-pages).

## Управление

- Выбрать фигуру, затем нажать на клетку: это левый верхний угол её ограничивающего прямоугольника.
- Либо перетащить фигуру на поле. При касании якорь находится на одну клетку выше пальца.
- Зелёный предпросмотр означает допустимый ход; подсвечиваются будущие очищаемые линии. В недопустимом месте подсветка отсутствует.
- Три темы переключаются под коллекцией, выбор сохраняется в localStorage.
- Кнопка «?» открывает правила. После конца партии доступна новая игра.

## Правила и принятые трактовки

Поле 8×8, без лимита размещений. Партия заканчивается только при отсутствии допустимого размещения для всех оставшихся фигур. Точный старт «Лотос»: y=2 и y=5, x=0…5; первая рука — горизонтальная двойка, вертикальная двойка, одиночная клетка. Всего **33 уникальных ориентации** из заданного каталога; ручного вращения нет. Новая тройка гарантирует одну помещающуюся фигуру, если такая есть; её позиция в тройке случайна, две другие фигуры независимы.

Строки и столбцы удаляются одновременно в модели; их объединение используется для удаления клеток. Анимация удаляет клетки резкой поблочной волной от клеток последней поставленной фигуры вдоль каждой завершённой строки/столбца к краям поля. Пересечение удаляется один раз, при приходе первой волны. Ввод блокируется только до конца эффекта. Очки: `5 × клетки + 100 × линии² × комбо + 300 при пустом поле`.

**Комбо:** первая очистка ×1, следующая ×2, затем ×3 и т. д. Один или два хода без очистки сохраняют множитель, третий сбрасывает его до ×1. Это явно зафиксированная трактовка стартового множителя. Очки не расходуются.

## Структура

- `src/core/shapes.ts` — каталог и уникальные повороты.
- `src/core/game.ts` — чистая модель: размещение, выдача, очки, линии, конец партии; RNG передаётся параметром для воспроизводимости.
- `src/render/canvas.ts` — объёмные блоки, предпросмотр, размещение, растворение, тряска и частицы. `prefers-reduced-motion` отключает движение и частицы.
- `src/ui/input.ts` — Pointer Events: мышь и касания, выбор и drag-and-drop.
- `src/main.ts`, `src/style.css` — интерфейс и связывание модулей.
- `src/meta/catalog.ts` — шесть скинов с редкостями и ровно три картинки зданий.
- `src/meta/store.ts` — версионированное хранилище отдельных балансов, валидация и миграция прежних сохранений → v3.
- `src/meta/economy.ts` — независимый расчёт наград за линии, взвешенный выбор типа и прогресс картинки.
- `src/ui/collections.ts` — постепенное проявление картинок, полёт частичек, три SVG-сундука и кнопка готовности.
- `src/meta/chests.ts` — стоимость открытия, таблица шансов редкостей, выпадение скина и возврат за дубликат.
- `src/ui/chests.ts` — сетка скинов, блокировки, анимация открытия, показ награды и применение.
- `public/art/` — собственные SVG: оранжерея с тремя растениями, маяк, дом у парка.

Счёт партии не сохраняется; настройки, балансы частичек, полученные скины и собранные картинки сохраняются в `localStorage`, ключ `block-build.meta.v3`. При миграции из v1/v2 прежние демонстрационные разблокировки сбрасываются до стартового «Лотоса», а накопленные частички сохраняются. Старые записи остаются нетронутыми; новые разблокировки v3 сохраняются между запусками.

## Экономика коллекций

Единственная расходуемая валюта — частички коллекций, у каждого типа свой баланс. Очки не тратятся. У нового игрока все три баланса равны нулю.

| Картинка | Вероятность за линию | Нужно частичек | Сундук |
| --- | --- | --- | --- |
| Оранжерея | 50% | 100 | Обычный |
| Маяк | 40% | 100 | Редкий |
| Дом у парка | 10% | 100 | Легендарный |

- Каждая очищенная строка и каждый столбец дают **1 × текущий комбо** частичек. Тип выбирается отдельно для каждой линии. Пример: две линии при комбо ×3 дают два случайных пакета по 3, всего 6. Пересечение считается двумя линиями для награды, как и для очков.
- При отсутствии очищенных линий частички не выдаются. Бонус очков за пустое поле не добавляет валюту.
- Однотипные пакеты одного хода объединяются только для анимации. Награда сохраняется сразу, до начала полёта, поэтому обновление страницы не теряет её. Накладывающиеся полёты не дублируют и не теряют начисления.
- Картинка проявляется из центра мозаикой 10×10 по мере сбора: одна частичка раскрывает 1% её площади. В 100/100 изображение полностью открыто, доступна кнопка «Забрать».
- Вероятности остаются 50/40/10 даже для готовых картинок. Избыток выше 100 сохраняется отдельным остатком «В запасе», а прогресс ограничен 100/100. Это выбранная политика прототипа без сгорания валюты.
- На desktop награда летит в видимую картинку. Для картинки вне viewport или ниже края списка появляется миниатюра-получатель; основной экран не прокручивается. При reduced motion начисление отображается сразу, без перелёта.
- «Забрать» **сразу списывает 100 частичек этой картинки и открывает её сундук**. Выпадает один скин: новый разблокируется, дубликат даёт **25 частичек только исходной картинки**. Собранная картинка навсегда остаётся открытой, а её шкала показывает частички до следующего сундука. Следующие 100 позволяют повторное открытие.
- Списание и выдача сохраняются одной операцией до анимации. Повторное нажатие во время показа награды не открывает второй сундук; перезагрузка не позволяет повторно получить ту же награду.
- Прототип предполагает одну активную вкладку игры; синхронизация одновременных записей из нескольких вкладок не добавлена.

## Скины и шансы сундуков

Изначально доступен только **Лотос**. Остальные заблокированы до выпадения:

| Скины | Редкость |
| --- | --- |
| Лотос, Пески, Терракота | Обычная |
| Сумерки, Океан | Редкая |
| Аврора | Легендарная |

| Сундук | Обычный скин | Редкий скин | Легендарный скин |
| --- | ---: | ---: | ---: |
| Обычный | 75% | 20% | 5% |
| Редкий | 35% | 45% | 20% |
| Легендарный | 10% | 50% | 40% |

Это начальная настройка баланса прототипа. Сначала определяется редкость, затем равновероятно выбирается один из скинов этой редкости. В пул входят уже полученные скины и стартовый «Лотос»: дубликаты возможны с самого первого сундука, их вероятность зависит от состава личной коллекции. Гарантий нового скина и защиты от повторов нет. Проценты редкостей отображаются в окне сундука.

Новый скин можно сразу применить или оставить на потом; экипировка сама не меняется. Получение/применение скина не меняет очки, фигуры и состояние партии.

Проверки экономики включают распределения 50/40/10 и таблицы сундуков, начисление по комбо, стоимость, дубликат +25, остатки, повторные открытия, миграцию/повреждённые данные, полёты, перезагрузку во время анимации, блокировки, применение скинов и сохранение собранных картинок.

## Проверки и история

`docs/session/` содержит исходные промпты, публичные ответы, успешные и неуспешные проверки и снимки desktop/mobile. `events.jsonl` пополняется только добавлением строк, каждая содержит SHA-256 предыдущей строки. `recordedAt` — время записи события, а не вымышленная дата отправки сообщения. Источник фиксации начала — реальное показание часов: **2026-09-15 20:23:37 UTC / 23:23:37 МСК**. Общий бюджет трёх промптов — 60 минут активной работы; ожидание следующего промпта исключается.

Референс механики: предоставленная пользователем видеозапись, изучены кадры 8 и 16–20 секунд. Отдельный скриншот оформления в первом сообщении недоступен; оформление построено по текстовому описанию. Мобильные проверки выполняются эмуляцией touch в Chrome, не на физическом устройстве.

## Ежедневный уровень

Верхний баннер заменяет вступительный текст: цель дня, редкий сундук и таймер до местной полуночи. Уровень занимает место основного поля и коллекций. Выход и закрытие награды возвращают текущую основную партию с её полем, фигурами и счётом. Перезагрузка страницы начинает игровую партию заново; метапрогресс сохраняется.

- Типы целей чередуются по дате: 1000/1250/1500 очков за 15 ходов, 5/7/9 синих клеток за 20 ходов, комбо ×5 за 50 ходов.
- Дата определяет раскладку и последовательность фигур. Повторные попытки одинаковы. Начальные фигуры соответствуют пяти незаполненным строкам: у каждого уровня есть решение; далее работает обычная выдача фигур с генератором от даты.
- Синие клетки засчитываются только при очистке линий, пересечение строки и столбца считается один раз. В ежедневном режиме используется палитра «Лотос», чтобы цвет цели не зависел от скина.
- Цель, выполненная последним разрешённым ходом, засчитывается. При исчерпании ходов или отсутствии места доступна новая попытка. Начатый до полуночи уровень сохраняет исходные условия до выхода.
- За победу автоматически открывается бесплатный **редкий сундук**, один на дату. Скин и отметка прохождения сохраняются вместе до анимации. Повторная загрузка не выдаёт награду ещё раз. Дубликат приносит 25 частичек «Маяка»; коллекция при этом не помечается собранной. Обычные частички за линии в ежедневном режиме не начисляются.
- Даты прохождения хранятся в `block-build.meta.v3`; старые сохранения получают пустой список. Это локальный прототип: календарь и сохранение зависят от устройства, серверная проверка даты отсутствует.

Проверки ежедневного режима: решаемость и уникальность 365 раскладок, все три цели, лимит ходов, блокировка поля, одноразовая награда, обновление даты, повторные попытки, возвращение основной партии, desktop и ширины 390/320 px.
